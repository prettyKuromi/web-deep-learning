# SDD-035：实验流程重入重置与提示可见性

- 状态：已完成
- 编号：035
- 创建日期：2026-10-22

## 1. 背景与目标

离开实验流程后再次进入，页面仍显示上一次训练的进度、快照或当前结果，容易让用户误以为正在查看一轮新实验。模型能力提示位于粘性训练按钮之后，在桌面配置栏滚动到底部时会被按钮栏遮住。此改动让每次进入实验流程都从空白训练状态开始，并让能力提示完整可见。

## 2. 范围

### 包含

- 从“模型与数据”确认进入实验流程时，清除上一次流程的运行状态和当前结果。
- 离开实验流程后，再次从顶层导航进入时，同样清除运行状态和当前结果。
- 保留当前模型、模型参数、数据集和已保存的历史实验记录。
- 调整“拟合完成，不支持暂停、继续或单步；可停止计算”能力提示与粘性训练控制栏的布局关系，保证提示不被遮挡。

### 不包含

- 删除或修改已保存的历史实验记录。
- 重新初始化模型、参数、数据集或评估设置。
- 改变训练控制能力及其文案含义。

## 3. 用户流程

1. 用户完成模型和数据集选择并进入实验流程，开始或查看一轮实验。
2. 用户切换到其他顶层页面后再次进入实验流程，训练状态、进度、快照、错误、指标、当前结果和选中步骤均回到初始状态。
3. 用户保留当前模型、参数和数据集，可直接开始新一轮训练；之前已完成的实验仍可在历史记录中查看。
4. 用户查看不可暂停/继续/单步的模型能力提示时，整段文字均可见且不被训练控制按钮遮挡。

## 4. 技术方案

- 将进入实验流程的动作集中处理，在从其他页面切入时调用现有训练重置逻辑，再更新顶层页面状态。
- “确认数据集并进入实验流程”复用同一个进入动作，避免导航和确认入口行为不一致。
- 只清空运行时实验状态和当前实验引用；保留数据、模型配置和 store 中的实验列表。
- 调整能力提示与粘性按钮栏的文档流顺序或包裹关系，使提示不落入按钮栏的遮挡区域。保持桌面三栏工作区布局。

## 5. 数据结构与接口

- 不新增持久化字段或公共 API。
- 复用 `App` 中的 `resetTraining` 和顶层导航处理逻辑；如需提取进入函数，仅供 `App` 内部使用。
- 能力提示继续由 `SinglePageWorkbench` 根据模型能力渲染。

## 6. 错误处理

- 重入时如有未完成的训练，通过现有 abort controller 中止旧任务并清空 Worker 引用，避免旧训练状态继续覆盖新流程。
- 已保存历史记录不随当前流程重置而移除。
- 能力提示仍按正常文本换行显示，不使用截断、省略号或固定高度裁切。

## 7. 验收标准

1. 从“模型与数据”进入实验流程时，旧训练状态被清空，状态显示等待训练，快照和当前结果为空。
2. 从历史记录等页面重新进入实验流程时，旧进度、快照、错误、指标、当前结果和选中训练步骤不再显示。
3. 重入后选定的模型、模型参数、数据集及已保存历史实验保持不变。
4. 实验流程的模型能力提示完整可读，不与粘性训练控制栏重叠；在 1920×1080 桌面视口通过实际浏览器检查。
5. 相关测试、生产构建及 `git diff --check` 通过，验证结果写回本 SDD。

## 8. 测试策略

- Vitest/Testing Library 覆盖“历史记录 → 实验流程”重入后训练状态和快照清空，以及“模型与数据”再次确认进入时状态清空。
- 在桌面浏览器使用 1920×1080 检查完整能力提示、训练控制栏和三栏布局；必要时以 1440×900 复查桌面断点。
- 运行相关测试、`npm run build` 和 `git diff --check`。

## 10. 未决问题

- 无。重入时保留用户配置和历史记录，只重置当前实验运行状态。
