# SDD-018：实验工作台视觉布局精修

- 状态：已实现
- 编号：018
- 创建日期：2026-08-09

## 1. 背景与目标

现有三页工作台虽然已区分数据集、实验流程和历史记录，但页面内容横向铺满，数据集选择控件、上传控件与主操作按钮缺乏宽度层级；训练页的栏宽和按钮密度也不够像桌面机器学习工具。

本次调整在不改变训练、数据处理和页面流程的前提下，建立紧凑、稳定且易扫读的实验工作台视觉体系。

## 2. 范围

### 包含

- 应用外壳设置最大内容宽度，在超宽屏保持居中留白。
- 数据集页改为受限宽度的选择区域；选择器与上传控件采用紧凑横向布局，确认按钮使用内容宽度。
- 实验流程页固定为窄配置栏、宽训练画布和紧凑洞察栏；中等屏幕改为两栏，窄屏改为单列。
- 统一卡片圆角、内边距、表单高度、次级按钮和主按钮的视觉密度。
- 顶部导航改为紧凑的分段导航，当前页有清晰状态。

### 不包含

- 修改算法、训练状态、Worker、数据格式或持久化格式。
- 增加新的可配置项、图表或页面。
- 修改现有中文界面文案，除为布局分组增加的无障碍语义类名外不改变交互。

## 3. 用户流程

1. 用户进入数据集页，在居中的内容区域选择内置数据集或上传 CSV。
2. 用户查看紧凑且完整的数据集预览，点击尺寸适中的确认按钮进入实验流程。
3. 用户在实验流程页从左侧配置模型，在中央观察训练，在右侧阅读解释和结果。
4. 用户在窄屏设备上按配置、训练、结果的顺序纵向浏览，页面不出现横向溢出。

## 4. 技术方案

- `App.css` 负责全局尺寸令牌、应用容器、通用表单与卡片样式。
- `pages.tsx` 为数据集页增加专用布局类，使数据集页的宽度策略独立于历史页。
- `pages.css` 负责数据集页、顶级导航和历史页的页面级排版。
- `SinglePageWorkbench.layout.css` 负责三栏比例与断点，不引入新的 React 状态。
- `SinglePageWorkbench.css` 负责实验流程页内部卡片、按钮组、状态和参数区域的密度。

宽屏（至少 1280px）容器最大宽度为 1560px；实验流程页栏宽为约 280px / 自适应主区 / 300px。768px 至 1279px 使用两栏，结果栏跨两列；小于 768px 使用单列。

## 5. 数据结构/API

不新增数据结构、训练 API 或状态动作。仅为现有数据集页根元素增加 `dataset-page` CSS 类。

## 6. 错误处理

现有 CSV、空数据和训练错误提示保持原行为。视觉调整不得隐藏 `role="alert"`、`role="status"` 或禁用状态。

## 7. 验收标准

- 超宽屏下应用主内容居中且最大宽度受限，页面不再全宽铺开。
- 数据集页的选择区域最大宽度受限，内置数据集与上传控件不会各自占满页面宽度。
- 确认数据集和训练主操作按钮在桌面端按内容宽度显示；训练控制其余按钮保持紧凑。
- 实验流程宽屏显示窄左栏、最大中央训练区和紧凑右栏。
- 1280px、768px 与 375px 下无横向滚动，控件不会超出容器。
- 现有数据集选择、模型切换、训练控制和无障碍角色测试继续通过。

## 8. 测试策略

- Vitest：新增数据集页专用布局类的断言，保证布局入口不会被移除；保留现有实验流程语义和训练控制测试。
- 构建与静态检查：运行 `npm test -- --run`、`npm run lint`、`npm run build` 和 `git diff --check`。
- 浏览器验证：在 Playwright Chromium 可用时覆盖 1440px、1280px、768px、375px 的无横向溢出。

## 9. 实现状态、验证命令和已知限制

- 实现状态：已实现全局内容限宽、数据集页紧凑选择布局、实验流程三栏比例与响应式断点，并保留现有交互与训练逻辑。
- 验证命令：`npm test -- --run`（21 个测试文件，115 项通过）；`npm run lint`；`npm run build`；`git diff --check`。`npm run e2e` 因本机缺少 Playwright Chromium 可执行文件未能启动。
- 已知限制：CSS 布局的像素级效果需要在安装 Chromium 后补跑 Playwright 视口验证；本次未修改算法、训练和持久化逻辑。
