# SDD-000：Web Deep Learning 总体设计

- 状态：Approved for planning
- 版本：1.0
- 创建日期：2026-08-08
- 适用阶段：MVP 及后续演进

## 1. 背景与目标

目标是构建一个面向机器学习初学者、兼顾开发者的 Web 实验工作台。用户可以在网页中生成或导入数据，选择经典机器学习模型，调整参数，观察训练过程和决策边界，查看评估指标，并保存可复现实验。

第一阶段不追求完整深度学习平台，而是先验证以下闭环：

```text
数据 → 预处理 → 配置模型 → 浏览器训练 → 过程与结果可视化 → 保存/导出实验
```

## 2. 产品范围

### 2.1 MVP 包含

- 单页实验工作台。
- 内置二维数据集：线性可分、XOR、月牙形、环形、随机噪声。
- CSV 导入：选择两个数值特征和一个分类标签，跳过缺失/非法行并报告处理结果。
- 二分类与多分类。
- KNN、逻辑回归、线性 SVM。
- 手动参数调整和单次训练。
- 训练状态、耗时和可取消操作。
- 逻辑回归/SVM 的 loss 与指标迭代曲线。
- 二维散点图、预测结果、错误点和决策边界。
- Accuracy、Precision、Recall、F1、混淆矩阵。
- IndexedDB 本地保存、删除、查看实验。
- JSON 实验导入与导出。

### 2.2 明确后置

账号、云端存储、后端训练、GPU、深度学习模型、协作分享、自动部署、回归任务、复杂类别特征处理、网格搜索（属于第二阶段）。

## 3. 用户与成功标准

主要用户是希望直观理解机器学习过程的初学者，次要用户是需要快速做小规模实验的开发者。

MVP 成功标准：新用户能在 5 分钟内选择月牙形数据、训练逻辑回归、看到 loss 和决策边界、查看分类指标、保存实验、修改参数重训并导出/导入 JSON。

## 4. 技术路线与选型

### 4.1 推荐方案

React + TypeScript + Vite，Zustand 管理应用状态，ECharts 绘制曲线/散点/混淆矩阵，Canvas 绘制决策边界，Dexie 封装 IndexedDB，Papa Parse 解析 CSV，Web Worker 执行训练，Vitest 做单元测试，Playwright 做关键流程测试。

### 4.2 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 自实现 TypeScript 算法 | 训练过程可控、教学解释性强、依赖少 | 初期需要实现算法和指标 | MVP 采用 |
| JavaScript 机器学习库 | 开发快、算法现成 | 过程可视化和 API 可控性较弱 | 作为后续替换/补充 |
| Pyodide/WASM | 可复用 Python 生态 | 首次加载大、复杂度和性能成本高 | 暂不采用 |

核心算法通过统一接口隔离，未来可以替换为后端或 WASM 实现。

## 5. 系统架构

```text
React UI
├── 数据集面板
├── 模型与参数面板
├── 训练控制面板
├── 训练曲线与决策边界
├── 指标与混淆矩阵
└── 实验历史
        │
        ▼
Zustand Store ── Worker Client ── Web Worker（Trainer）
        │                              ├── KNN
        │                              ├── Logistic Regression
        │                              └── Linear SVM
        ▼
Dexie/IndexedDB + JSON Import/Export
```

训练器建议遵循以下概念接口：

```ts
interface Trainer {
  train(config: TrainConfig, emit: (snapshot: TrainSnapshot) => void): Promise<TrainResult>;
  predict(model: ModelState, samples: FeatureMatrix): PredictionResult;
}
```

训练快照至少包含迭代次数、loss、训练指标和可选模型参数；最终结果包含模型配置、数据摘要、随机种子、指标、混淆矩阵、训练耗时和可序列化模型参数。

## 6. 数据与训练约束

- MVP 只处理二维数值特征和一个分类标签。
- 默认支持 1,000～5,000 条数据；训练和预测目标响应时间小于 1 秒。
- 需要标准化时使用训练集统计量，并将统计量保存到实验结果。
- 数据集划分必须记录比例和随机种子。
- 多分类统一采用 One-vs-Rest，并明确宏平均指标口径。
- KNN 没有 epoch：展示预测耗时、邻居信息和决策边界。
- 逻辑回归使用 sigmoid 与梯度下降；SVM 使用 hinge loss 与梯度下降/次梯度下降。
- 训练通过 Web Worker 执行，避免阻塞 UI；Worker 消息需要支持开始、快照、完成、失败和取消。

## 7. 页面与交互

单页工作台布局：左侧配置数据和模型，中间显示散点/决策边界与训练曲线，右侧显示指标和实验历史，底部显示训练日志与错误信息。

关键交互：

1. 选择内置数据或上传 CSV。
2. 选择特征/标签并确认数据摘要。
3. 选择模型和参数。
4. 开始、取消或重新训练。
5. 查看过程曲线、决策边界、错误点和指标。
6. 保存实验、添加备注、导出或导入 JSON。

中文优先，参数旁提供简短概念解释和合理默认值；高级参数可折叠。

## 8. 持久化与可复现

IndexedDB 保存实验元数据、数据摘要、必要的数据集快照、模型参数、训练快照和最终指标。JSON 导出格式必须包含版本号，导入时校验版本和必需字段。相同数据、参数和随机种子应得到一致结果。

## 9. 错误处理

- CSV 无可用数值特征、标签为空或有效行不足时阻止训练并给出原因。
- 参数超出范围时在控件附近提示，不启动训练。
- Worker 训练异常显示可读错误，并允许重新训练。
- 用户切换数据或模型时，对未保存结果给出轻量提示。
- 大数据量超出 MVP 建议范围时给出性能提示，而不是静默失败。

## 10. 验收指标

### 功能

- 至少 5 个内置数据集可运行。
- 3 种模型均可训练并输出预测。
- 二分类和多分类均能显示指标与混淆矩阵。
- CSV 导入、字段选择、非法行处理可用。
- 实验保存、删除、导出、导入可用。

### 性能

- 1,000～5,000 条二维数据训练大多数情况下小于 1 秒。
- UI 在训练期间保持可交互。
- 决策边界绘制目标小于 500ms。

### 质量

- 算法、指标、CSV 解析和序列化逻辑有单元测试。
- 关键用户流程有端到端测试。
- 同随机种子结果可复现。

## 11. 分阶段路线

### Phase 0：原型

完成工作台布局、静态数据和图表占位，验证信息架构。

### Phase 1：MVP

完成内置数据、CSV、KNN/逻辑回归/线性 SVM、训练可视化、指标、IndexedDB 和 JSON。

### Phase 2：实验增强

增加网格搜索、多实验对比、备注标签、ROC/AUC、PR 曲线和更多数据集。

### Phase 3：模型扩展

增加决策树、随机森林、朴素贝叶斯、PCA 和聚类。

### Phase 4：深度学习

接入 TensorFlow.js 或 ONNX Runtime Web，探索 WebGPU 和简单神经网络可视化。

### Phase 5：后端训练

引入 FastAPI、任务队列、PyTorch/scikit-learn、账号和云端实验存储。

## 12. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 主线程阻塞 | MVP 即使用 Web Worker |
| 决策边界计算慢 | 限制网格分辨率，使用 Canvas |
| 多分类复杂 | 统一 One-vs-Rest，并固定宏平均定义 |
| 教学与专业性冲突 | 默认简洁，提供可展开参数解释 |
| IndexedDB 容量有限 | 保存摘要和必要快照，大数据后置到后端 |

## 13. 后续功能 SDD 拆分

实现时按以下顺序创建独立规格：

1. `001-workbench-shell.sdd.md`：工作台布局与状态模型。
2. `002-dataset-management.sdd.md`：内置数据集、CSV 解析和预处理。
3. `003-training-engine.sdd.md`：Trainer 接口、Worker 通信和取消机制。
4. `004-knn.sdd.md`：KNN 算法和邻居可视化。
5. `005-logistic-regression.sdd.md`：逻辑回归训练与曲线。
6. `006-linear-svm.sdd.md`：线性 SVM 训练与曲线。
7. `007-visualization.sdd.md`：散点、边界、曲线和混淆矩阵。
8. `008-experiment-persistence.sdd.md`：IndexedDB、JSON 导入导出。
9. `009-mvp-verification.sdd.md`：测试、性能和验收。

每份 SDD 必须使用 `specs/templates/feature.sdd.md` 模板，并在实现完成后回填验证记录。

## 14. 未决事项

- 首选图表库最终在 ECharts 与 Plotly 之间做原型验证后确定；当前默认 ECharts。
- 是否支持拖拽上传 CSV，留到数据管理 SDD 明确。
- 实验 JSON 的精确版本迁移策略，在持久化 SDD 中定义。
