# SDD-026：可信训练过程反馈

## 背景与目标

训练界面必须忠实呈现 Worker 正在执行的算法步骤，让初学者能判断训练阶段、进展与结果来源。

## 范围

- 以 Worker 快照和控制事件驱动训练中状态；禁止计时器生成进度。
- 明确准备、训练、暂停、停止、完成、失败、保存失败状态，训练结果与过程分区呈现。
- 展示当前/总迭代、进度、最新损失/指标、最近步骤趋势；非迭代算法说明其实际单位。
- 节流 Worker 到 UI 的快照更新，完整保留最终结果。
- 参数或数据变化后清除当前结果；保存异常不覆盖训练成功状态。
- 中文错误提示与响应式训练反馈区域。

## 用户流程

配置数据与模型后启动训练，界面显示准备及训练状态。用户观察 Worker 推送的进度与损失，可在支持的模型上暂停、单步、继续或停止。训练完成后查看结果；存储失败单独显示。

## 技术方案

沿用 React、Zustand、Web Worker 及既有训练控制协议。训练状态通过 Worker 快照/控制消息转移；回调以固定时间窗口合并 UI 更新但不丢弃最终快照。对参数型迭代模型，以配置迭代数为总量；无法提供迭代意义的模型不显示虚假进度。

## 数据结构/API

训练状态包含 status、progress、snapshots、metrics、error；快照沿用 `TrainSnapshot.iteration/loss/metrics/timestamp`。UI 的当前值根据最近实际快照计算。

## 验收标准

- Worker 快照驱动的迭代单调增长，进度不超过 100%；UI 不用定时器伪造进度。
- 支持控制的模型暂停后不增长，单步只推进一轮，继续恢复；停止后不再有训练状态更新。
- 完成、取消、失败、保存失败分别反馈；失败保留错误上下文。
- 修改数据/模型/参数后当前结果失效。
- 训练过程展示清晰的当前值、总量、损失及趋势，窄屏可用。

## 测试策略

运行 Vitest、lint、build，并通过 Playwright 验证训练状态与控制交互。

## 未决问题

各模型支持的控制能力以实际训练器为准；非迭代算法总量应显示为不适用。

## 实现状态、验证命令与已知限制

- 实现状态：已实现准备/初始化阶段提示、Worker 快照驱动的节流训练反馈、当前迭代/总量/进度/损失/分类指标、明确的损失图标题与数据说明、保存失败独立提示、停止时失效当前结果及失败上下文查看。
- 验证：`npm test -- --run`（26 个测试文件、164 项通过）；`npm test -- --run src/features/workbench/SinglePageWorkbench.test.tsx`（12 项通过）；`npm run lint`（通过，已有 test-results/acceptance-run.mjs 未使用 fs 导入警告）；`npm run build`（通过）。

- 未决问题：无。
