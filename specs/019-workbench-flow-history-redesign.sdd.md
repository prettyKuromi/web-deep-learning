# SDD-019：实验流程与历史记录工作台重构

- 状态：已实现
- 编号：019
- 创建日期：2026-08-09

> 2026-10-16 补充：滚动策略、卡片高度与交互状态的最新约束以 [SDD-024](024-workbench-interaction-polish.sdd.md) 为准；普通内容统一随页面纵向滚动。

## 1. 背景与目标

上一轮视觉精修改善了宽度和间距，但实验流程页仍把“更换数据集”作为普通大按钮放在训练标题旁，历史记录页则把记录列表和详情纵向堆叠，用户点击记录后需要滚动到页面底部才能看到结果。

本次进行结构级重构：让实验流程页拥有明确的上下文栏和步骤感，让历史记录页采用列表 + 详情的同屏工作台结构。

## 2. 范围

### 包含

- 实验流程页：将当前数据集展示为上下文条，使用紧凑的“更换”入口，不再占据标题区域的主要视觉权重。
- 实验流程页：增强配置、训练、洞察三部分的层级和标题，使步骤关系清晰。
- 历史记录页：左侧实验列表、右侧选中实验详情；列表独立滚动，详情保持可见。
- 无历史记录时保留清晰的空状态；有记录但未选择时显示选择提示。
- 保留现有数据集切换、训练控制、历史详情内容和回调接口。
- 适配桌面、平板和手机：桌面左右分栏，窄屏上下排列且详情紧跟列表。

### 不包含

- 修改训练算法、数据格式、持久化协议或新增页面。
- 改变历史记录的保存、删除、导入导出行为。
- 引入新的 UI 依赖。

## 3. 用户流程

1. 用户进入实验流程页，先在顶部上下文条确认当前数据集，再在左侧配置模型。
2. 用户在中央区域开始训练，右侧查看解释与结果。
3. 用户进入历史记录页后，左侧直接看到实验列表；点击任一记录，右侧立即展示详情，无需滚动到页面底部。
4. 用户在手机上按“列表 → 详情”顺序浏览。

## 4. 技术方案

- `SinglePageWorkbench.tsx` 保留现有三列语义，但将数据集切换移动到 `workflow-context-bar`，按钮改为紧凑次级操作。
- `HistoryPage.tsx` 组合新的 `history-workspace`：`history-list-pane` 与 `history-detail-pane`。选中详情仍由 App 传入，不新增全局状态。
- `pages.css` 统一历史工作台、上下文条、列表项选中态和响应式规则。
- 详情面板使用 `position: sticky`（桌面）保持在可视区域；列表区域 `overflow-y: auto`。

## 5. 数据结构/API

不新增数据结构和 API。继续使用 `HistoryPageProps.selectedDetail` 与 `onSelect`，通过 CSS 和结构调整改善可见性。

## 6. 错误处理

沿用现有训练错误、数据集错误和空状态提示。历史详情缺失时显示“请选择一条实验记录查看详情”，不抛出异常。

## 7. 验收标准

- 实验流程页不再显示占据标题区域的大型“更换数据集”按钮。
- 当前数据集在训练区上方以紧凑上下文条展示，切换入口仍可用。
- 历史记录有数据时，列表与详情在桌面端同屏显示；点击记录后详情位于右侧可视区域。
- 历史列表可独立滚动，不推动详情到页面底部。
- 无历史记录和未选择记录时均有明确中文提示。
- 375px、768px、1280px 下不出现横向溢出，所有既有组件测试保持通过。

## 8. 测试策略

- Vitest：覆盖上下文条的切换回调、历史列表与详情同屏语义、未选择记录提示。
- 完整验证：`npm test -- --run`、`npm run lint`、`npm run build`、`git diff --check`。
- Playwright：补跑主流程和历史记录可见性；若本机缺少 Chromium，记录环境限制。
