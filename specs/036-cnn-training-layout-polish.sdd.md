# SDD-036：CNN 训练画布布局细节修复

- 状态：已实现并验证
- 编号：036
- 创建日期：2026-10-22

## 1. 背景与目标

CNN 网络画布中的插入按钮在鼠标悬停时展开辅助文字，使按钮宽度变化并造成视觉抖动。训练快照增加时，画布下方时间线逐渐变高，挤压上方的 CNN 网络画布。此改动让插入按钮保持加号外观，并为 CNN 时间线预留稳定空间。

## 2. 范围

### 包含

- CNN 网络插入按钮在默认、悬停和键盘聚焦状态下始终显示加号，宽度固定；插入位置仍通过无障碍名称表达。
- CNN 训练画布初始就预留固定高度的时间线区域，避免快照增加时改变画布区域高度。
- 时间线内容超过可视区域时，在时间线内部滚动。

### 不包含

- 修改 CNN 网络结构编辑、插入行为、训练算法或快照数据。
- 改变非 CNN 模型的时间线布局。
- 增加新的依赖或持久化状态。

## 3. 用户流程

1. 用户在 CNN 网络画布中将鼠标移到层间插入按钮上，按钮仍显示加号且尺寸不变；点击后仍可选择要插入的层。
2. 用户开始训练，网络画布与时间线区域保持稳定高度。
3. 随着训练快照增加，时间线在预留区域内显示或滚动，不再逐步挤压上方网络画布。

## 4. 技术方案

- 保留插入按钮的 `aria-label`，移除悬停时展开的可视文字，并固定按钮宽度。
- 为 CNN 训练画布和时间线卡片添加专用样式类。
- CNN 画布网格明确设置时间线轨道高度，并在没有训练快照时也渲染时间线卡片以提前占位；时间线内容超出区域时启用内部纵向滚动。
- 不改动普通模型的网格轨道和时间线显示条件。

## 5. 数据结构与接口

- 不新增数据字段、持久化格式或公共 API。
- 仅复用现有 `TrainSnapshot` 快照列表和 `NetworkFlowCanvas` 插入按钮无障碍名称。

## 6. 错误处理

- 空快照时显示空时间线区域，避免训练开始后新增网格轨道。
- 快照较多时通过内部滚动访问较早条目；仍只展示最近八条。
- 插入按钮继续通过无障碍名称标识其目标位置，鼠标与键盘用户均可操作。

## 7. 验收标准

1. 插入按钮在初始、悬停和键盘聚焦时始终只呈现加号，悬停前后宽度一致，辅助名称仍能说明插入位置。
2. CNN 未开始训练和训练快照增加时，时间线卡片占用的外部布局高度保持固定。
3. 时间线条目较多时仅时间线内容区域滚动，训练网络画布高度不随快照数量逐渐减少。
4. 非 CNN 模型的时间线仍仅在有快照时显示，原有布局不变。
5. 相关测试、生产构建与 `git diff --check` 通过，并在本规格中记录验证结果。

## 8. 测试策略

- Vitest/React Testing Library 验证插入按钮可见文本只含加号且保留位置无障碍名称；验证 CNN 在空快照时已渲染时间线占位，非 CNN 空快照时不渲染时间线。
- 在浏览器中核对 hover 前后按钮边界尺寸一致；比较 CNN 空快照与多快照时训练画布、时间线卡片尺寸，并确认长时间线在内部滚动。
- 运行相关 Vitest、`npm run build` 与 `git diff --check`。

## 9. 实现记录

- 实现状态：已实现。CNN 插入控件始终显示固定 30px 加号；CNN 时间线预留固定 152px 轨道并在无快照时占位，长列表在内部滚动。
- 验证命令：`npm.cmd test -- src/features/training/NetworkFlowCanvas.test.tsx src/features/workbench/SinglePageWorkbench.test.tsx`（2 个文件、23 项测试通过）；`npm.cmd run build` 通过；`npm.cmd run lint` 退出码 0；`git diff --check` 通过。
- 浏览器检查：Chrome 1366×900 下加号 hover 前后均为 30px；时间线 1 条增长到 5 条时卡片保持 152px，网络图高度保持 210.6px；列表内容高度 102px、可视高度 92px，确认由内部滚动承载。
- 已知限制：CNN 初始画布会为时间线保留 152px 高度，以换取训练期间稳定布局。Lint 检查报告一条既有警告：未跟踪文件 `test-results/acceptance-run.mjs` 中导入的 `fs` 未使用。
