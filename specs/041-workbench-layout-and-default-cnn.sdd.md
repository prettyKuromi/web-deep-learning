# SDD-041：工作台时间线、历史滚动与 CNN 默认选择

- 状态：草稿
- 编号：041
- 创建日期：2026-10-27

## 1. 背景与目标

训练时间线在窄布局中可能出现条目挤压和文字重叠，历史实验记录区域不便纵向浏览。当前默认数据集为表格型月牙数据，系统因此默认推荐 KNN；用户希望首次进入时默认使用 CNN。CNN 只支持图像数据，因此默认数据集同步调整为内置手写数字图像集，使模型和数据开箱即用。

## 2. 范围

### 包含

- 调整训练时间线条目间距和换行，使不同快照标签在窄屏及桌面布局均清晰可读。
- 确保历史实验列表可独立纵向滚动；实验详情内容过长时也可纵向滚动。
- 将首次启动及重置后的默认内置数据集设为手写数字图像集，并由现有兼容性推荐逻辑选中可视化 CNN。

### 不包含

- 修改训练算法、快照数据、历史记录格式、持久化行为或 CNN 架构。
- 重做历史页面整体布局，或改变用户手动选择其他兼容模型和数据集的流程。
- 添加新的滚动依赖、虚拟列表或新的数据集。

## 3. 用户流程

1. 用户开始训练并产生多个快照后，训练时间线条目之间保留间距；较窄的内容区域内标签按需换行，不会互相覆盖。
2. 用户进入“历史记录”页，可在记录列表中上下滚动查看旧实验；选择记录后，详情内容较长时可在详情区域内上下滚动。
3. 用户首次打开页面或重置工作台时，默认看到手写数字数据集和可视化 CNN；确认后可直接进入 CNN 实验流程。用户仍可按数据兼容性选择其他模型或数据集。

## 4. 技术方案

- 为 `.single-page-timeline` 的横向换行布局增加明确的行列间距，为条目限制最小宽度并允许长文本换行；保留每条快照的完整 `aria-label`。
- 让 `.history-list-scroll` 成为实验列表唯一的纵向滚动容器，避免其内部 `ResultsPage` 的固定高度和滚动样式形成嵌套滚动；保留 `.history-detail-panel` 的纵向滚动，并确保相关 Grid 子项可收缩。
- 将 `workbenchStore` 的默认数据集从 `moons` 改为 `digits`。沿用 `recommendedModel(dataset)` 按数据类型推荐 CNN 的逻辑，不新增独立的默认模型状态。

## 5. 数据结构与接口

- 不新增数据字段、公共 API 或持久化格式。
- 复用现有内置数据集 `digits`、`recommendedModel`、`TrainSnapshot` 和历史实验数据结构。

## 6. 错误处理

- 默认 CNN 与手写数字图像数据匹配，避免首次进入时出现模型与数据不兼容。
- 用户选择其他模型或数据集时继续沿用现有兼容性检查与提示。
- 列表为空时保留现有空态；历史列表和详情的滚动不改变导入、删除、选择与比较行为。

## 7. 验收标准

1. 时间线最多显示的八条快照在窄屏和桌面布局下均有清楚分隔；长标签可换行且不遮盖相邻条目。
2. 时间线条目的完整可访问名称与快照信息保持一致。
3. 历史记录数量超过列表可视区域时，用户可在列表区域纵向滚动到任意记录；页面固定外壳不会截断列表。
4. 选中内容较长的实验后，详情区域可纵向滚动查看完整详情。
5. 首次启动和重置后，内置数据集为 `digits`，模型选择为可视化 CNN；用户确认数据后可进入 CNN 工作流。
6. 用户可以继续选择兼容的其他模型与数据集，原有历史记录操作和数据结构不变。
7. 相关测试、生产构建、Lint 与 `git diff --check` 通过；在桌面和窄屏浏览器中核对实际换行和滚动行为。

## 8. 测试策略

- 使用 Vitest 验证默认数据集为手写数字集、默认模型由现有推荐逻辑解析为可视化 CNN；验证时间线仍保留快照数量和完整无障碍名称。
- 使用 Playwright 或真实浏览器在 1366×768 与 390×844 视口下检查时间线条目边界不重叠、历史列表能滚到末条记录、详情可滚到内容末尾、页面无横向溢出。
- 运行相关 Vitest、`npm.cmd run build`、`npm.cmd run lint`、必要的 Playwright 验证与 `git diff --check`。
